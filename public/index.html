全流程覆盖

覆盖考勤全流程

从活动发布、签到核验，到申诉审批与审计留痕。

活动签到

自主选择签到 / 在途中 / 请假，支持单场、长期与子活动排期；签到时间窗口由服务端计算，客户端时间不可信。

活动范围核验

默认关闭，需在运维端启用。启用后签到记录标注「范围内 / 范围外」作为参考，不阻断签到流程；定位采集须本人授权，精度低于阈值（默认 200 米）时拒绝采集。

防代签（设备绑定与留痕）

账号首次签到绑定设备识别码，设备变更记录留痕并更新绑定，供管理端核查；登录侧同一账号至多允许一台移动端与一台桌面端。

请假 / 补签申诉

支持图片材料、两级裁决（初审 / 终审）、裁决锁定与申诉复议，审核意见全程可追溯。补签申请可由运维端关闭，关闭后仅保留请假流程。

分级通知与邮件

站内消息中心默认启用；配置 SMTP 后启用邮件通道，按接收方在线状态自动选择投递渠道。通知类型与层级可分层配置，个人亦可选择接收渠道。

权限与账号

五级角色权限分级、管理范围（Scope）收敛、权限工单与向下授权；上级缺位时自动代管，该机制可由运维端关闭。

数据流审计

除仅个人内部生效操作外，其余操作无论触发方是谁均全量留痕；管理端只读、仅运维者可删除。敏感字段页面展示默认打码（可在运维端关闭），底层记录始终全量保留。

前端零 CDN 依赖

页面、样式与前端库（地图、日期组件、几何运算）均随项目分发，不引用外部 CDN。地图底图瓦片需联网加载，默认使用高德瓦片服务，可替换为自备瓦片源。

用户端清爽模式

用户端默认启用：隐藏无权限入口与次要说明，签到选项紧凑排布。学生可在「界面偏好」中关闭，仅影响本人界面。

按需启用

主流程开箱即用，其余按需决定

安装完成即可开展签到、请假与审批。下面两类功能分别需要手动开启、或可按需关闭，随时都能改回来。

默认关闭 · 需要手动开启

不开启不会影响签到、请假、审批等主流程。

  • 活动范围核验部署方在运维端「系统安全」中开启。开启后签到记录标注「范围内 / 范围外」，仅作参考，不在范围内仍可正常签到。
  • 管理端查看学生定位仅运维者可开启，且需先开启范围核验。开启后管理员可在地图上查看签到位置，每次查看同样留痕。
  • 邮件通知在部署配置中填入邮件服务信息后启用；未配置时通知全部走站内消息，不影响送达。
  • HTTPS 与安全 Cookie默认以 HTTP 提供服务，局域网或校内环境可直接用；在配置中开启后需自备证书。
  • 维护模式运维端设定起止时间与公告文案，期间服务端拦截业务请求。
  • 隐私告知 / 公告栏由运维者维护文案，填写后在对应页面展示。

默认开启 · 可按需关闭

可按管理习惯调整，随时恢复默认。

  • 补签申请关闭后学生只能提交请假，不再受理补签。
  • 上级缺位自动代管上级缺位时自动下放审批权限；关闭后相关审批可能无人受理。
  • 敏感字段打码展示关闭后页面以明文显示姓名与学号；底层记录不变，仍全量保留。
  • 各类提醒通知可按通知类型与接收层级逐项关闭；工单回复与系统消息为强制项，不可关闭。
  • 用户端清爽模式由学生本人在「界面偏好」中关闭，仅影响本人界面，不隐藏任何功能。
  • 个人通知渠道每人自选：站内 + 邮件 / 仅站内 / 不接收。
始终开启且不可关闭：活动签到、请假与两级裁决、站内消息中心、五级角色权限分级、数据流全量留痕。
需要访问外部网络的仅两处：地图底图瓦片（默认高德，可替换为自备瓦片源）与邮件发送（需自行配置邮件服务）。其余全部在自有服务器内完成。
三端分立

面向三类角色的独立工作台

用户端、管理端与运维端按角色划分，权限边界清晰，互不越权。

用户端

学生（用户端）

面向学生，覆盖签到、请假、申诉与通知等日常操作。

  • 签到、活动范围核验（需启用）
  • 请假、销假与补签申诉
  • 通知消息与个人考勤统计
  • 个人资料、绑定邮箱与设备管理
  • 清爽模式（默认开启，可一键关闭）
管理端

班委 / 辅导员（管理端）

面向班委、小班主任与辅导员，负责活动发布、考勤查看与审批。

  • 发布活动、班级签到视图
  • 审批请假、补签与工单
  • 成员管理、角色与权限
  • 考勤统计；查看学生签到位置需运维端开启并授权
运维端

运维者（运维端）

面向部署与维护人员，负责系统初始化、配置、账号体系与故障处理。

  • 部署配置与一键初始化
  • SMTP 邮件服务配置
  • 系统开关：定位核验、维护模式、提醒项
  • 故障排查与运维命令

零配置启动

无需配置文件即可启动；仅在调整端口、子路径或邮件服务时，才需要在项目根目录提供 .env。

1

获取部署包

下载并解压，内含服务端、三端与三册图文说明书（PDF）。

2

安装依赖

运行 npm ci 严格按 lockfile 安装（生产可加 --omit=dev）。

3

启动服务

npm start，首次启动自动建库并创建初始运维者账号（未设密码）。

4

激活运维者

打开 /register.html，按「运维者」身份完成邮箱验证并设置密码。

5

配置与调优

运行 npm run config 交互式配置邮件、HTTPS、子路径等；TUI 自动检测 Nginx 并配置反代（^~ 优先级），失败给可复制指令；服务未运行时主动启动。

# ✅ 推荐 Node.js ≥ 20（自动检测版本）
# ⓪ 自动定位项目目录（不确定路径时执行）
find / -maxdepth 5 -name package.json -path "*/check-in/*" 2>/dev/null
cd <上一步输出的目录>
# ① 安装依赖（锁定版本，不要用 npm install）
npm ci
# ② 启动服务 + 初始化数据库 + 配置向导一步完成
npm start
# ③ 后续修改配置 / 升级后重新运行向导 / SMTP 预检
npm run config
# ④ 单独重置管理员密码 / 清空打卡记录 / 查看日志
npm run init
# ⑤ 修改 .env 后重启服务（TUI 会自动检测托管方式并重启）
# 若需手动重启，按实际托管方式选择：
pm2 restart checkin # PM2 / 宝塔面板
systemctl restart checkin # systemd
supervisorctl restart checkin # supervisor
docker restart checkin # Docker / Podman / containerd
forever restart checkin # forever
rc-service checkin restart # OpenRC (Alpine/Gentoo)
nssm restart checkin # Windows Service
# nodemon / ts-node-dev → 自动重载无需手动 · 1Panel/screen/tmux 等请查阅 README.md

数据看板与报表导出

考勤原始数据可在服务端做聚合，生成可视化看板与 Excel / PDF 报表，方便辅导员与教务留存、汇总分析。

增减角色

角色不限于内置的学生 / 班委 / 小班主任 / 辅导员 / 运维者，可按学校需要增删职能角色（如教务、宿管等）；新增角色须在角色等级与权限集上一并扩展，非简单改名。

常见问题

常见问题解答

是否需要持续联网？
需要。系统为客户端—服务端架构，签到、请假、审批与站内消息都必须连接网络访问服务器，无法离线使用。仅活动范围地图的底图瓦片由外部地图服务（默认高德）提供，离线时该区域留空、范围判定仍由服务端完成，不影响核验。邮件通道仅在配置 SMTP 后启用。
哪些功能默认关闭？
活动范围核验、管理端查看学生定位、邮件通知、HTTPS、维护模式、隐私告知与公告栏默认关闭，需手动启用。补签申请、自动代管、敏感字段打码、各类提醒与清爽模式默认启用，均可按需关闭。逐项说明见「功能开关」。
地图与定位是否涉及境外服务？
定位由浏览器与终端系统提供，联网时精度更高，该环节不受本系统控制；系统仅在签到时采集一次坐标，随签到上传至自有服务器。地图底图是唯一访问外部服务的环节，默认使用高德瓦片（国内，无需密钥，可替换为自备瓦片源）。查看学生定位此前使用 OpenStreetMap 瓦片，现已统一为高德，并完成 WGS-84 → GCJ-02 坐标转换对齐。
清爽模式是否隐藏功能？
不会隐藏任何可用功能。该模式仅收起无权限入口与次要说明文字，签到、请假、申诉等流程完整保留；学生可在「界面偏好」中关闭以恢复完整界面。
未配置 SMTP 是否影响通知？
不影响通知送达：未配置 SMTP 时全部通知通过站内消息投递。邮箱验证码激活账号等环节依赖 SMTP，因此生产环境建议配置。
活动范围核验的判定规则是什么？
范围判定结果仅作参考，不在范围内仍可正常提交签到。该项默认关闭，需在运维端启用；启用后定位精度低于阈值（默认 200 米）将被拒绝，且须本人授权方可采集位置。签到时间窗口由服务端计算，不信任客户端时间。
是否持续采集学生位置？
不会。系统不做后台持续定位，也不记录行动轨迹；仅在签到时采集一次位置并随签到上传。用户端「查看活动范围」地图提供前台连续定位，仅用于学生本人查看自身位置，数据仅在本机显示、不上传，关闭地图即释放监听。
数据安全如何保障？
私有部署使数据库留存于自有服务器；页面展示统一脱敏；关键操作全量审计留痕；权限按角色分级、按管辖范围收敛。
是否支持二次开发？
支持。MIT 协议下源码完整交付，可基于自身场景二次开发，包括调整各类功能开关的默认值。
