1. 运维端定位与登录

运维端拥有系统最高权限，负责部署、系统级设置与安全策略，并处理管理端无法覆盖的全局事项。首次登录前需先在终端完成配置，未配置班级名时运维者无法登录。

推荐先执行 npm run config 走一遍配置向导（班级名、数据库、邮件、活动范围等），再用 npm start 启动服务（首次启动自动建库并写入初始运维者账号）。注意：npm run init 不是日常初始化命令，而是「一键初始化（空白部署态）」——会清空全部业务数据与账号、仅重建运维者，请仅在需要彻底清空时执行。

2. 部署与运行

系统为单体服务，私有化部署，数据留存于自有服务器。

命令作用
npm ci按 lockfile 安装依赖（生产环境推荐）。
npm run config终端配置向导：写入班级名、数据库路径、邮件 SMTP、活动范围等。
npm run init一键初始化（空白部署态，破坏性）：清空全部业务数据与账号、仅重建运维者（无密码），恢复出厂设置；执行前需键入「初始化」并校验运维者密码，且自动备份。仅在需彻底清空时执行，切勿当作日常启动命令。
npm start直接启动服务（配置完成后）。
# 典型部署流程
npm ci
npm run config     # 交互式配置（可随时重跑）
npm start          # 启动服务（首次自动建库并写入初始运维者账号）
配置向导不修改业务数据，仅写配置项；可反复运行以调整设置。

14.2 常见问题

  • 运维者无法登录？ 多半是未配置班级名，先执行 npm run config。
  • 邮件发送失败？ 在「运维」中检查 SMTP 主机/端口/加密/账号授权码，并发送测试邮件。
  • 范围核验不生效？ 确认已开启范围核验并为活动绑定了围栏。
  • 如何备份 / 迁移？ 备份整个 data/ 目录（含 app.db 与 .jwt-secret、SECRET_KEY 等密钥文件）；迁移服务器须连同这些密钥一起复制，否则已签发令牌与旧密文将失效。建议定期导出数据流与考勤表归档。
  • 数据存在哪里？ 全部留存于本服务器数据库，系统不做云端上传。
